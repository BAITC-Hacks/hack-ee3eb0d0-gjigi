# Этап 1 — архивные погодные прогнозы без утечки

Воспроизвести:
```bash
python scripts/build_weather_archive.py   # скачать архив (кэшируется)
python scripts/check_weather.py           # проверки → эта папка
```

## Источники

| Модель | API | Что получаем | Период |
|---|---|---|---|
| **ECMWF IFS 9 км** (`ecmwf_ifs`) | Single Runs | полный прогон как был выпущен, 00/06/12/18z, 78 ч | 2024-03-14 … 2026-03-02, 2575 прогонов |
| ECMWF IFS 0.25° (`ecmwf_ifs025`) | Previous Runs | значение, спрогнозированное за 1/2/3 суток | 2024-03-06 … 2026-03-02 |
| GFS (`gfs_seamless`) | Previous Runs | то же | то же |
| ICON (`icon_seamless`) | Previous Runs | то же | то же |

Переменные: ветер 10/100 м (скорость и направление), порывы, температура 2 м, давление, влажность,
высота пограничного слоя, CAPE (последние три только у ECMWF 9 км).

- **Семантика Previous Runs проверена:** значения `previous_dayN` в точности совпадают с прогоном
  `floor_6h(t) − N суток` из Single Runs.
- **Пропуски:** в марте–августе 2024 в архиве нет части промежуточных прогонов ECMWF 06z/18z
  (основные 00z/12z есть). В такие дни `get_forecast` берёт предыдущий опубликованный прогон,
  то есть заблаговременность чуть больше, но утечки нет. В тестовом периоде архив полный.

## Защита от утечки

Прогноз, выпущенный в момент `as_of`, видит строку архива, только если
`init_time + задержка(модель) ≤ as_of`. Задержки консервативные: ECMWF 8 ч, GFS и ICON 6 ч.
Из доступного берётся самый свежий прогон на каждый час.

- Тесты `tests/test_weather_store.py`: выбор последнего опубликованного прогона; результат не меняется,
  если удалить все будущие прогоны; для каждого из 28 тестовых выпусков нет строк из будущего.
- `test_issue_runs.csv` — для каждого выпуска с 31.01 по 27.02: какие прогоны использованы, когда они опубликованы,
  диапазон заблаговременности. Пример: выпуск 31.01 в 04:00 UTC → ECMWF 18z от 30.01 (доступен с 02:00 UTC),
  заблаговременность 24–71 ч.

## Часовой пояс SCADA: UTC+6

Сравнили часовой ветер и температуру SCADA с краткосрочным ECMWF (заблаговременность < 6 ч) при разных сдвигах
(`01_tz_offset.png`):

| сдвиг | 4 | 5 | **6** | 7 |
|---|---|---|---|---|
| корр. ветра | 0.726 | 0.788 | **0.791** | 0.749 |
| корр. температуры | 0.967 | 0.979 | **0.984** | 0.983 |

Максимум ветра по параболе — около 5.6 ч. Среднечасовое значение SCADA центрировано на полчаса позже метки
(мгновенный NWP — на метке), поэтому истинный сдвиг ≈ 6 ч. Время SCADA — **UTC+6**, фиксированное:
вероятно, система не перешла на UTC+5 в марте 2024. В `config.yaml`: `scada_utc_offset_h: 6`.
Выпуск в 10:00 по времени станции = 04:00 UTC. Остаточное рассогласование до получаса модель на этапе 2
поглотит признаками NWP соседних часов (t−1, t, t+1).

## Выводы для этапа 2

1. **Ансамбль моделей ощутимо лучше любой одной модели:** MAE на D+1 1.89 против 2.18 у лучшей одиночной.
   Все 4 модели идут в признаки, стэкинг/GBM выберет веса сам.
2. **ECMWF 9 км систематически занижает ветер** на ~1 м/с, сильнее зимой (−1.8 м/с в декабре, `03_ecmwf_error_by_month.png`).
   Нужна калибровка с учётом сезона, часа суток и направления ветра.
3. **D+2 заметно хуже D+1**, поэтому горизонт (или заблаговременность) — обязательный признак, а интервалы на D+2 должны быть шире.
4. **Температура SCADA на 3–5 °C выше NWP** при корреляции 0.97. Это датчик в гондоле, а не температура воздуха.
   Для плотности воздуха берём температуру и давление из NWP.
5. Данные для обучения готовы: `data/weather/issued_forecasts.parquet` — 723 исторических выпуска
   в точности по боевому протоколу (обучение = применение).
